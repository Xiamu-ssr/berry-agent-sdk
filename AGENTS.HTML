Berry Agent SDK 对齐页

唯一入口：本页。AGENTS.md 只跳转到本页。

一句话

SDK 是 managed-agent harness。它负责 agent 生命周期、事实源、执行面、恢复、审计和治理；产品只选择根目录和展示/连接方式。

当前状态
本地 managed-agent harness 已基本对齐。
还不是云端托管平台。
边界
SDK 管 agent。Claw 管产品壳、前台 client、REST/WS、桌面/移动体验。
剩余
平台部署问题：真实 Docker/K8s/SSH worker、租户调度、vault/secret proxy。

这张图是架构参照，不是产品截图。

docs/anthropic-managed-agents-notes.md 是推导过程和改造记录；本页是最终对齐结论。

映射关系：Harness = @berry-agent/runtime + ManagedAgentRuntime；Session = SDK session/event facts；Tools/MCP = Hand/Capability；Sandbox = ExecutionEnvironment；Orchestration = RuntimeOrchestrator/Supervisor/Scheduler。

不可变原则

  • 产品只传 AgentHome(root)；SDK 规定内部目录结构。
  • messages.json 是 LLM 上下文事实源；events.jsonl 是 UI/审计/timeline 事实源。
  • 产品不复制 session、event、memory、team、MCP、safety 的存储语义。
  • 新增持久化/transport/domain 数据结构，先写 zod schema，再推导类型。
  • 直接 tool 会被包成 SDK-owned Hand；能力暴露和执行走统一 policy/audit。
  • 默认 command/MCP stdio 环境不带长期密钥；密钥通过 CredentialStore 或显式 scoped env。

判断一段代码该放哪

问题答案
影响 agent turn、context、tool loop、resume？放 SDK。
定义持久化 agent 数据结构？放 SDK，并先写 schema。
只是展示、连接、按钮、布局、浏览器壳？放 Claw。
需要真实容器/远程 worker 部署？平台层实现，接 SDK ExecutionEnvironmentProvider。
